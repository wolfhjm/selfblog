# 认知地图与验证闭环路线草案

## 背景

当前 MVP 已有打卡、AI 对话、原则库、行动实验和洞察保存。下一阶段目标不是简单增加列表，而是把真实事件、规律、原则、经验教训、实验和复盘串成一套可演化的个人认知系统。

核心方向：从日记、打卡、对话、实验复盘里的小事件出发，提取可观察事实、主观反应、洞察、经验教训，再关联到规律和原则，并通过行动实验验证这些认知是否对自己成立。

底层解释框架见 [系统内在逻辑草案](SYSTEM_MODEL.md)。认知侧优先用 ABC / CBT 拆事件、解释、情绪和行为；行动实验侧优先用 Fogg Behavior Model，并用 COM-B、健康状态、需求/价值和知识图谱作为补充框架。

## 已确认产品决策

### 1. 规律和原则分开

规律偏通用模式或 mental model，例如 `Garbage in, garbage out`、反馈回路、复利、主动加工。

原则偏个人化行动准则，例如“交付 AI 产物前，必须能解释核心逻辑”。

一个规律可以关联多个原则、多个经验教训、多个实验和多个小事件。一个原则也可以被多个规律、事件和实验支撑。

### 2. 小事件是一等对象

日记、打卡、对话、实验复盘中的具体事例需要被抽出来成为独立对象，而不是只藏在原始文本里。

小事件用于支撑：

- 规律识别
- 原则草稿
- 洞察总结
- 经验教训
- 实验建议
- 后续复盘验证

### 3. 主客观层次

暂定分层：

- 小事件：偏客观，描述发生了什么
- 感受/反应：偏主观，描述当时怎么感受、怎么解释
- 洞察：主观认识，描述我通过这件事理解了自己什么
- 经验教训：半主观行动判断，描述下次该避免或采用什么
- 规律：偏客观/通用，描述更普遍的模式
- 原则：个人化准则，描述我基于规律和经验形成的行动标准

### 4. 三种来源都支持提取

AI 提取候选内容的来源包括：

- 日记 / 打卡
- 自我探索对话
- 实验复盘

三种来源都可以提取小事件、感受、洞察、经验教训、规律候选、原则草稿、实验建议和关联建议。

### 5. 手动触发 AI 提取

V1 不做保存后自动提取。用户在认为内容有价值时手动触发。

推荐入口：

- 打卡 / 日记：提取小事件
- 对话页：提取洞察 / 事件
- 实验复盘：提取验证结果
- 统一收件箱：处理候选

### 6. 提取后先预览

AI 提取后不直接污染正式库。先展示预览列表，用户可以编辑、删除、调整关联、确认入库或放入收件箱。

预览采用统一列表，不分 Tab。通过标签和下拉筛选区分候选类型。

### 7. 候选处理方式

支持单条确认和批量确认。

建议规则：

- 小事件：可批量确认
- 普通经验教训：可批量确认
- 原则草稿：默认单条确认
- 规律候选：默认单条确认
- 实验建议：默认单条确认
- 关联建议：可批量确认，但必须能编辑和撤销

### 8. 去重策略保守

去重偏保守，宁可留一点重复，也不要误合并。

建议规则：

- 同一来源且高相似度：可自动合并
- 不同来源但语义重复：提示合并候选，由用户确认
- 同主题但层级不同：不要合并，保留为不同对象并建立关联

### 9. 规律可手动新增

用户必须能手动新增规律。AI 可以帮助完善规律卡片。

AI 完善规律时建议生成：

- 标题
- 一句话定义
- 适用场景
- 常见误用
- 对我的启发
- 可衍生原则
- 可验证实验
- 相关问题
- 可能例外

### 10. 原则允许无来源，但应能后补来源

原则可以先无来源创建，但需要标记为未绑定来源。后续可以通过 AI 或手动方式补充来源事件、规律、经验教训或实验验证。

### 11. 规律和原则需要验证状态

规律和原则不是静态真理，需要有验证状态。

建议状态：

- 未验证
- 有例子
- 实验中
- 部分支持
- 强支持
- 待修订
- 废弃

实验完成后，AI 可以建议更新关联规律/原则的验证状态，但必须由用户确认后生效。

### 12. 实验支持一次性和多日两种形态

实验任务允许 AI 辅助拆分，但用户必须能修改。

实验任务能力：

- 新增
- 编辑
- 删除
- 调整顺序
- 勾选完成
- 标记跳过
- 写备注

实验类型：

- 一次性 checklist
- 多日 / 多阶段行动计划

实验验证结果建议分为：

- 支持
- 部分支持
- 不支持
- 不确定

验证重点不是“我成功了吗”，而是“这个规律/原则对我是否成立、在什么条件下成立”。

## 新增页面规划

### 认知地图 / 知识网络

新增主页面，V1 不做复杂节点图，先做列表 + 详情 + 关联。

左侧对象列表：

- 规律
- 原则
- 经验教训
- 洞察
- 感受/反应
- 小事件
- 实验

右侧详情：

- 定义 / 内容
- 来源
- 关联对象
- 验证状态
- 相关实验
- 相关事件
- 操作：编辑、关联、生成实验、提炼原则

原则和实验保留独立页面，因为它们也是行动入口；其它类型主要在认知地图中筛选管理。

### 候选收件箱

统一处理 AI 提取候选。

能力：

- 按类型筛选
- 按来源筛选
- 按状态筛选
- 编辑候选
- 删除候选
- 单条确认
- 批量确认
- 合并相似项
- 调整建议关联

## 建议数据模型方向

### 新增核心表

建议后续新增：

- `patterns`：规律 / mental model
- `cases`：小事件 / 事例
- `reactions`：感受 / 反应
- `lessons`：经验教训
- `candidates`：AI 提取候选
- `experiment_tasks`：实验任务拆分
- `object_links`：统一关联表

已有表需要扩展：

- `principles`：增加验证状态、来源提示、关联入口
- `experiments`：增加实验类型、验证结果、关联对象
- `insights`：明确作为洞察类型，或后续纳入统一对象模型

### 统一关联表草案

`object_links` 可以表达任意对象之间的关系：

- source_type
- source_id
- target_type
- target_id
- relation_type
- confidence
- status
- created_by
- created_at

关系类型示例：

- supports
- contradicts
- derived_from
- validates
- inspired_by
- evidence_for
- example_of
- suggests_experiment

## 分阶段实施计划

### 当前完成度快照（2026-05-30）

整体完成度约 55% - 60%。核心链路已经能跑：打卡、探索对话、AI 候选提取、候选确认、认知地图、对象关联、实验和原则入口都已经存在；但“事件拆分更细、感受串联、洞察证据链、自由对话选段继续分析、验证闭环自动回流”还没有完全做深。

已落地：

- 认知地图基础对象和对象关联
- 候选收件箱及候选确认
- AI 候选提取结构化 payload
- 候选“继续分析”入口
- 探索历史删除和确认弹框
- 打卡日期按应用时区处理
- 历史对话发送失败后的可恢复处理
- 高增长列表分页：探索历史、候选收件箱、认知地图、打卡记录、日记小结、原则库、实验库、公开页，以及对应列表 API

下一步更值得继续推进的方向：

- 把候选从“单条卡片”升级为“事件链/候选组”，让一个来源对话拆成多件事、多层感受和多条推断。
- 在探索页增加“结构化追问模式”，围绕客观环境、具体事件、身体信号、感受、解释、隐藏需求/恐惧继续问。
- 在认知地图里展示一条洞察来自哪些事件和证据，而不只是孤立对象。
- 给实验复盘接 AI 分析，把结果回流为验证状态和证据链接。
- 给关联选择器做全库搜索，避免分页后只能关联当前页对象。

### 阶段 3：AI 辅助生成

目标：让 AI 成为结构化助手。

目标：让系统能反向修订认知。

- 实验复盘后 AI 建议验证状态

- 认知地图展示证据链
- 支持修订、废弃或升级原则
